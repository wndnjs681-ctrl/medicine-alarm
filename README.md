# 복약노트 (Medicine Alarm)

한국어 약 복용 관리 웹앱입니다. React와 Vite로 실행하며 별도 서버, 데이터베이스, API 키는 필요하지 않습니다.

## 기능

- 약 이름, 용량, 하루 여러 복용 시간, 요일, 메모 등록 및 수정
- 21일 복용·7일 휴약처럼 반복하는 주기와 시작 날짜 설정
- 날짜별 복용 일정과 완료/취소 기록
- 약 삭제 후에도 완료 기록 보존
- 브라우저 복용 알림과 중복 알림 방지
- Android 예약 알림: 앱을 닫아도 복용 알림, 알림에서 복용 완료, 재부팅 후 예약 복원
- 월별 복용 캘린더, 약별 필터, 주별 복용률, 날짜별 완료·취소 기록
- JSON 형식 데이터 내보내기
- 데스크톱과 모바일 화면
- Android 홈 화면 위젯: 오늘 진행률, 다음 미복용 약, 앱을 열지 않고 복용 완료

## 실행

Node.js 24 LTS와 npm을 사용합니다. 이 저장소의 기존 체크아웃에서 실행하세요.

```bash
npm ci --cache /tmp/medicine-alarm-npm-cache --no-audit --no-fund
npm run dev -- --port 5173 --strictPort
```

홈 디렉터리를 쓸 수 없는 클라우드 환경에서도 위 캐시 경로로 설치할 수 있습니다. 포트가 사용 중이면 다른 포트를 지정하세요. 외부에 노출할 때는 신뢰할 수 있는 환경의 접근 제어를 사용하세요.

## 검증

```bash
npm test
npm run build
npm run test:e2e
```

단위 테스트는 일정, 날짜, 복용 기록, 알림 시점, 저장 데이터 검증을 검사합니다. Playwright는 데스크톱과 모바일에서 등록·수정·삭제, 기록 유지, 내보내기·가져오기, 알림 호출/중복 방지, 화면 크기를 검사합니다. 알림 테스트는 브라우저 Notification API를 대체해 호출을 확인하며 실제 운영체제 알림 전달을 보장하지 않습니다.

클라우드 환경에서는 기본 제공 `/usr/bin/chromium`을 자동 사용합니다. 다른 Chromium은 `PLAYWRIGHT_CHROMIUM_EXECUTABLE`로 지정할 수 있습니다. Chromium이 없는 일반 개발 환경에서는 먼저 `npx playwright install chromium`을 실행하세요. 브라우저 테스트는 임시 개발 서버를 4173 포트에서 실행하고 종료합니다.

## 저장 및 알림 조건

- 웹의 약과 기록은 현재 브라우저의 `localStorage`에만 저장됩니다. 서버 전송과 기기 간 동기화는 하지 않습니다. 브라우저 데이터를 지우기 전에 데이터를 내보내세요. 설정에서 복약노트의 JSON을 가져올 수 있으며, 확인 후 현재 목록과 기록을 교체합니다.
- 여러 탭에서 동시에 편집하면 마지막 저장으로 덮어쓸 수 있으므로 한 탭에서 사용하세요.
- **웹 브라우저** 알림은 HTTPS 또는 localhost의 지원 브라우저에서 알림 권한을 허용하고 이 페이지를 열어 두어야 작동합니다.
- 웹은 약 15초 간격으로 복용 시간을 확인합니다. 잠들거나 닫힌 브라우저에서는 알림을 보장하지 않으며, 다시 열었을 때 15분 이내의 미복용 일정만 알립니다. Android 앱은 네이티브 예약 알림을 사용하며 웹 알림을 중복 발송하지 않습니다.
- **복용 기록 > 캘린더**에서 완료, 일부 복용, 미기록, 예정, 휴약을 구분하고 날짜별 기록을 수정할 수 있습니다. 복용률은 완료 횟수 / 경과한 예정 복용 횟수이며 미래 시간과 휴약 기간은 제외합니다. 미기록은 실제 미복용의 확정이 아니라 완료 기록이 없다는 뜻입니다. 기록되지 않은 과거 일정은 현재 등록한 약 설정 기준으로 계산하므로 약 일정 수정·삭제 시 집계가 달라질 수 있습니다. 완료 기록은 약 삭제·시간 수정 후에도 캘린더와 목록에 남습니다.
- 설정한 복용 시작일부터 일정이 생성됩니다. 약 정보를 수정하면 일정에 반영되며 이미 완료한 기록의 이름과 용량은 보존됩니다.
- 반복 주기는 **주기 시작일**을 1일째로 계산합니다. 21일 복용·7일 휴약은 1~21일째에 복용하고 22~28일째에는 쉬며 29일째에 다시 복용합니다. 완료 기록을 누락해도 주기 날짜가 밀리지 않습니다. 기간은 복용 1~365일, 휴약 0~365일로 설정할 수 있습니다. 휴약 기간은 일정·알림·위젯 복용 완료에서 제외되고 재개일이 표시됩니다. 기존 요일별 약과 기록은 그대로 읽을 수 있습니다.
- 복용량과 복용 시간은 의료진의 안내를 따르세요. 이 앱은 처방을 판단하지 않습니다.

## 과거 복용 기록 수정

**복용 기록**의 캘린더에서 날짜를 선택한 뒤 약 옆의 연필 버튼을 누르세요. 목록 보기의 연필 버튼으로도 수정할 수 있습니다. 복용 날짜, 일정상의 복용 시간, 기록한 용량, 실제 복용 시각을 변경하거나 **복용 취소**로 기록을 제거할 수 있습니다. 용량 수정은 해당 기록에만 적용되며 등록된 약의 용량은 변경하지 않습니다.

선택한 날짜의 **기록 추가**는 빠뜨린 과거 복용을 기록합니다. 일정이 없는 날이나 삭제한 약도 다른 기록이 남아 있으면 선택할 수 있습니다. 미래 복용 날짜·실제 시각은 저장할 수 없으며 같은 약·날짜·복용 시간의 기록은 중복 저장하거나 덮어쓰지 않습니다. 기존 데이터 형식과 JSON 내보내기·가져오기는 그대로 유지됩니다.

## Android 홈 화면 위젯

Android 8.0 이상에서 사용하는 네이티브 위젯입니다. Capacitor로 기존 웹앱을 Android 앱에 포함하고, 같은 앱의 저장소를 위젯과 공유합니다. 인터넷 연결 없이 일정 확인과 복용 완료를 기록할 수 있습니다.

설치용 개발 APK는 `android/app/build/outputs/apk/debug/app-debug.apk`에서 생성됩니다. 휴대폰에 설치한 뒤 앱을 한 번 열고 약을 등록하세요. 앱 상단의 위젯 아이콘 또는 설정의 **위젯 추가**로 홈 화면에 추가할 수 있습니다. 또는 홈 화면을 길게 누르고 위젯 목록에서 **복약노트**를 선택하세요.

현재 버전은 1.3 (`versionCode=4`)입니다. 이전 개발 APK와 같은 패키지 및 서명이므로 앱을 삭제하지 않고 업데이트 설치하세요. 위젯 요청은 UI 스레드에서 실행하며 실제 등록 콜백과 위젯 개수로 확인합니다. 추가 화면만 열린 상태는 성공으로 표시하지 않습니다. 설정에 등록된 위젯 개수가 표시되고, 등록이 확인되지 않으면 홈 화면의 위젯 목록을 안내합니다. **홈 화면 열기**로 런처로 이동할 수 있습니다.

이전 버전에서 JavaScript의 정수 버전을 Android `Long` 값으로만 읽어 위젯 저장을 거부하던 문제를 수정했습니다. 실제 Capacitor `PluginCall`로 정수 JSON을 전달하는 회귀 테스트가 이 경로를 검사합니다.

- 기본 4×2 위젯이며 크기를 조절할 수 있습니다. 미복용 시간이 지난 약을 먼저 표시하고, 없으면 다음 예정 약을 표시합니다.
- 위젯의 **복용 완료**는 표시된 약 한 번의 복용을 기록합니다. 취소는 앱에서 할 수 있습니다. 중복 탭으로 기록이 중복되지 않으며, 날짜가 지난 버튼은 새 날짜에 잘못 기록하지 않습니다.
- 앱에서 변경하거나 위젯에서 완료하면 모든 위젯을 갱신합니다. 날짜·시간·시간대 변경 및 Android의 약 30분 주기 갱신에도 반영합니다. OS의 절전 정책으로 자동 갱신이 늦어질 수 있습니다.
- 앱이 오래된 데이터를 저장하려 하면 위젯의 최신 기록을 보존하고 다시 시도하도록 알립니다.
- Android 앱 데이터와 기존 Chrome 브라우저 데이터는 서로 다른 저장소입니다. 기존 기록은 웹앱에서 JSON으로 내보내고 Android 앱 설정에서 가져오세요. Android에서는 시스템 파일 선택기로 내보냅니다. 앱 삭제 시 앱과 위젯의 기록도 사라집니다.
- **설정 > 복용 알림**을 켜고 Android 알림 권한을 허용하세요. **테스트 알림**으로 알림창 표시를 확인하고, **정확한 시간 알림 > 허용**에서 알람 및 리마인더를 허용하면 절전 중에도 정확한 시간 예약을 사용할 수 있습니다. 알림 표시·소리는 Android 채널 설정을 따릅니다. 방해 금지 모드나 제조사 절전 정책으로 소리·팝업이 제한될 수 있습니다.
- AlarmManager와 고중요도 NotificationChannel을 사용합니다. 다음 복용 하나만 예약하고 전달 후 다음 시간을 예약하므로 21/7 주기도 앱을 다시 열지 않고 반복됩니다. 휴약일·완료·삭제된 약은 제외하며 변경·재부팅·업데이트·시간대 변경 후 예약을 갱신합니다. 알람 권한이 없으면 지연 가능한 예약을 사용합니다. 알림의 **복용 완료**는 위젯과 같은 데이터에 기록합니다. OS가 앱을 강제 종료하면 다시 열기 전에는 알림을 받을 수 없습니다.
- 이 APK는 개발용 디버그 서명입니다. Play Store 게시용 릴리스 서명과 스토어 배포는 포함하지 않습니다.

### Android 빌드

일반 개발 환경에서는 JDK 21, Android SDK 36 및 Build Tools 35.0.0/36.0.0을 설치하고 `ANDROID_HOME`을 설정하세요.

```bash
npm ci --cache /tmp/medicine-alarm-npm-cache --no-audit --no-fund
npm run android:build
```

이 클라우드 환경에서는 설치 스크립트가 서명·체크섬 및 TLS 검증을 유지하면서 `/workspace/.cache/medicine-alarm-android`에 도구를 준비합니다. 시스템 프록시와 세션 CA를 사용하며 홈 디렉터리를 변경하지 않습니다.

```bash
bash scripts/setup-cloud-android.sh
source scripts/cloud-android-env.sh
npm run android:build
```

`android:build`는 웹 빌드 및 Capacitor 동기화 후 APK 생성, Robolectric 위젯·예약 알림 테스트, Android lint를 실행합니다. Robolectric은 복용 완료, 날짜·요일·휴약 계산, 중복 방지, 오래된 앱 쓰기 거부, 실제 플러그인 정수 전달, 위젯 등록 상태 및 RemoteViews 화면 구성을 검사합니다. Playwright의 Android 브리지 시뮬레이션은 요청·미등록·등록 확인·조회 오류를 검사합니다. 클라우드 테스트는 실제 갤럭시에서 절전·재부팅 알림 전달·설치·핀 고정·파일 선택기 동작을 직접 검사하는 것을 대체하지 않습니다.

## 클라우드 환경

설치 명령과 시작 지침은 환경 설정의 `install_script`와 `start_skill`에 저장됩니다. 설정 초안을 저장해도 환경 게시나 GitHub 업로드가 자동 실행되지는 않습니다. 게시된 환경 스냅샷에서 파일과 의존성을 복원할 수 있으나 개발 서버는 작업마다 다시 시작해야 합니다.

각 클라우드 작업은 이미 격리된 환경입니다. 기존 `/workspace/medicine-alarm` 체크아웃을 사용하고, 사용자가 요청하지 않는 한 별도 Git worktree를 만들지 마세요.
